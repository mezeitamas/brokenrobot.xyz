Adding agents to a software project runs into the same limits as adding people. AI has made code cheap, so the bottleneck of software delivery has moved to deciding, verifying and coordinating - and those were always largely organisational. **AI amplifies whatever coordination an organisation already has.** More agents will not fix weak coordination, just as more developers never did.

- **Output scales.** Cursor's browser, Anthropic's C compiler and Gas Town show that hundreds of agents can produce millions of lines. But output scaled only where someone designed a structure for the agents: a hierarchy, one design authority, written intent and a strong test suite.
- **Brooks's mechanism still applies.** Work that cannot be split does not speed up: a Google Research study found that every multi-agent setup it tested made sequential planning 39–70% worse. Communication still costs: in Cursor's first design, twenty agents working as equals slowed to the throughput of two or three. And training becomes written context that someone must keep current.
- **The fixes are Brooks's own.** Planner agents directing workers are his surgical team; one design authority is his conceptual integrity. These fixes coordinate the agents. They cannot coordinate the people who decide what the agents are for: the goal, the trade-offs, the definition of done.
- **Speed outruns self-correction.** Our review and feedback loops were built for human pace. Weak coordination used to feel like a slow team; now it shows up as review queues, unused features and duplicate solutions, faster than we can correct them.
- **Output is not value.** Dario Amodei calls the share of AI-written code "a very weak criterion". Faros AI found engineers completing twice as many code changes while company metrics stayed flat. Agent output is usually competent; the problem is aim, not quality.
- **The organisation is what gets amplified.** Agents inherit its communication structure and its incentives. Unclear goals get implemented faster.

Culture follows structure, so change the structure. Judge AI work by what customers do, not by lines or pull requests. Write down shared intent before scaling the number of agents. Grow review capacity to match the new speed of production.

So the next time a late project meets the offer of a hundred more agents, the better question is not how many to start, but whether we know what we want them to build.
